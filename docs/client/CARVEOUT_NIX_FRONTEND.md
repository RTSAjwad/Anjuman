# Carve-out (shell agent → core agent): auto-rebuild + clear Vite cache in `nix run` frontend (core scope)

**From:** shell agent
**To:** core agent
**Status:** pending

## Context

The React shell consumes the shared Rust core over the wasm FFI bridge as two
generated artifacts — `boltffi pack wasm` (`generated/pkg/`) and
`codegen --language typescript` (`generated/types/`) — which are **gitignored** and
regenerated by `pnpm run build` (or `wasm:build` + `types:build`) in
`client/shells/react/`.

Whenever the core's `Event`/`ViewModel`/`Effect` or any shell-facing `*View`
changes layout (e.g. adding a field to `CardBrowserView`, or an `Event` variant),
the two artifacts must be regenerated **in lockstep**. If they aren't, the dev
server silently serves a mismatched ABI:

- stale `node_modules/.vite/deps/shared*` pre-bundles → "no rows" / an empty
  browser, and
- a changed `Event` enum → `unreachable` WASM panic on the first `update`.

This has now bitten three times. The root cause is that **`nix run .#client` and
`nix run .#anjuman` (the `frontend` process) only run `pnpm run dev`** — they never
rebuild the bindings, and they leave Vite's dep cache (`node_modules/.vite`)
untouched. So any core change desyncs the running frontend until a human
remembersto `rm -rf node_modules/.vite && pnpm run build` and restart.

## What to change (both in `flake.nix`, core scope)

Both entry points share the same "prepare + serve the React shell" job. Make them
first **install** deps, then **rebuild wasm/types**, **clear the Vite cache**, and
only then run the dev server.

### A. `apps.client` (files lines ~159-175)

Currently:

```nix
text = ''
  cd client/shells/react
  if [ ! -d node_modules ]; then
    pnpm install
  fi
  exec pnpm run dev "$@"
'';
```

Change to install → build → clear `.vite` → dev, e.g.:

```nix
text = ''
  cd client/shells/react
  if [ ! -d node_modules ]; then
    pnpm install
  fi
  pnpm run wasm:build
  pnpm run types:build
  rm -rf node_modules/.vite
  exec pnpm run dev "$@"
'';
```

### B. `process-compose."anjuman".settings.processes.frontend` (files lines ~261-276)

Same change, but note this block uses `working_dir = "client/shells/react";`
(no `cd`), so the script stays path-relative:

```nix
text = ''
  if [ ! -d node_modules ]; then
    pnpm install
  fi
  pnpm run wasm:build
  pnpm run types:build
  rm -rf node_modules/.vite
  exec pnpm run dev
'';
```

## Design decisions for you (core agent)

1. **`wasm:build` + `types:build` vs. a single `pnpm run build`.** The former two
   are faster (no `react-router build`/client+server bundling) and sufficient for
   a dev serve; the latter also produces `build/` (unused by `pnpm run dev`).
   Recommend the two separate steps for speed; `pnpm run build` is a fine
   alternative if you prefer one command.
2. **Performance.** These rebuilds run on every `nix run`. `boltffi pack wasm`
   is the slow step. A follow-up could skip the rebuild when the core hasn't
   changed (e.g. stamp the `shared/` source hash vs. a cached marker), but don't
   over-engineer now — correctness over speed. Flag it as a TODO in a comment.
3. **Path assumption.** `wasm:build`/`types:build` are `pnpm` scripts that `cd
   ../../shared` internally; they must run from `client/shells/react`. The
   `client` app already `cd`s there; the `frontend` process relies on
   `working_dir`, which already points there — both are correct.
